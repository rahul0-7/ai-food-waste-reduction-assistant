# AI Food Waste Reduction Assistant

A student prototype built for the **1M1B AI for Sustainability Virtual Internship** (July–September 2026).
**Primary SDG:** SDG 12 — Responsible Consumption and Production.

The app takes a simple list of food items a user currently has (with optional quantity,
freshness/age, and expiry info) and returns prioritized, practical suggestions: what to use
first, what can wait, leftover/reuse ideas, waste-reduction actions, a shopping/planning tip,
and an expected sustainability impact statement — grounded with a small curated knowledge base
of food-storage guidance (a lightweight Retrieval-Augmented Generation step) and generated by
Google Gemini via the official `google-genai` SDK.

> This is an internship prototype, not a production system. See `DOCUMENTATION.md` for
> limitations and responsible-AI considerations.

## 2. Run it locally

**Requirements:** Python 3.9+.

```bash
# 1. Move into the project folder
cd food-waste-assistant

# 2. (Recommended) create a virtual environment
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Add your API key
cp .env.example .env
# then open .env and set your key and model:
# GEMINI_API_KEY=your_key_here
# GEMINI_MODEL=gemini-3.6-flash   ← optional; this is already the default

# 5. Run the app
streamlit run app.py
```

Streamlit will open the app at `http://localhost:8501`.

**Getting an API key:** create one for free at https://aistudio.google.com/apikey
(Google AI Studio — no billing required for free-tier usage).

**No API key yet, or want to test the UI first?** The app still runs without a key — it will
automatically fall back to a simple, transparent rule-based suggestion mode instead of the AI
model, and will clearly say so on screen. This is intentional, so the app is demoable even if
the API is unreachable during a live demo (e.g. venue wifi issues).

## 3. Deploy it to the cloud (Streamlit Community Cloud — free)

This is the fastest way to get a public/shareable link for submission.

1. Push this project folder to a **public (or private) GitHub repository**. Make sure `.env` is
   **not** committed (only commit `.env.example`) — `.env` is already listed in `.gitignore`.
2. Go to https://share.streamlit.io and sign in with GitHub.
3. Click **"Create app"** → **"Yup, I have an app"**.
4. Fill in your repository, branch, and set the main file path to `app.py`.
5. Click **"Advanced settings"**, and in the **Secrets** box, paste:
   ```
   GEMINI_API_KEY = "your_key_here"
   ```
6. Click **Save**, then **Deploy**. Streamlit Community Cloud will install `requirements.txt`
   and launch the app at a `https://<your-app-name>.streamlit.app` URL you can share/submit.

If you ever need to change the key later, update it from the app's **Settings → Secrets**
in your Streamlit Community Cloud workspace.

**Alternative:** Render.com, Railway, or any host that runs a Python web process can also run
this app (`streamlit run app.py --server.port $PORT --server.address 0.0.0.0`), setting
`GEMINI_API_KEY` as an environment variable in that platform's dashboard. Streamlit Community
Cloud is recommended here because it is free and purpose-built for Streamlit.

## 4. Where the AI is used

- **LLM:** Google Gemini via the official `google-genai` SDK. Model: `gemini-3.6-flash`
  (the default). Override by setting `GEMINI_MODEL` in your `.env` file.
- **Prompt engineering:** `ai_engine.py` builds a system prompt that constrains the model to
  (a) only reason from user-provided inventory details, (b) never invent exact expiry dates,
  (c) never state uncertain food-safety information as fact, (d) never fabricate quantitative
  impact claims, and (e) return a structured JSON object so the UI can render it reliably.
- **Structured JSON output:** the API is called with `response_mime_type="application/json"`,
  and `_extract_json()` defensively strips any stray markdown fences before parsing, so the
  UI always receives a well-formed dict.
- **RAG (Retrieval-Augmented Generation):** `rag_engine.py` retrieves the most relevant entries
  from `knowledge_base.json` (a small, hand-curated set of general food-storage/waste-reduction
  guidance) using simple keyword matching, and includes them in the prompt as grounding context
  before Gemini generates its answer. This keeps suggestions factually grounded without requiring
  a vector database.
- **Fallback:** If no API key is set or the Gemini call fails for any reason, `ai_engine.py`
  returns a rule-based (non-AI) result instead, and the UI clearly labels which mode produced
  the result.

## 5. IBM Bob

[IBM Bob](https://www.ibm.com/bob) is an AI-powered development assistant and was used
throughout this project as a development partner.

**Work performed with IBM Bob during this project:**

- **Project initialization and architecture review** — ran `/init` to let Bob analyse the
  full codebase; Bob identified the module structure, data flow
  (`app.py → ai_engine.py → rag_engine.py → knowledge_base.json`), and coding conventions
  used across the project.
- **Code review and issue identification** — Bob reviewed `ai_engine.py`, `rag_engine.py`,
  and `app.py` and identified implementation issues, including the critical model-loading bug
  described below.
- **LLM migration (Anthropic → Google Gemini)** — Bob helped migrate the LLM integration from
  the Anthropic Claude API to the Google Gemini API (`google-genai` SDK), updating the prompt
  construction, API call, and response-parsing logic in `ai_engine.py` accordingly.
- **Environment variable and model configuration** — Bob helped configure `GEMINI_API_KEY` and
  `GEMINI_MODEL` environment variable handling, including updating `.env.example` and the
  `load_dotenv()` usage.
- **Debugging the model-loading bug** — Bob diagnosed a race condition where `MODEL_NAME` in
  `ai_engine.py` was evaluated at module import time, before `load_dotenv()` ran in `app.py`,
  causing the `GEMINI_MODEL` value from `.env` to always be ignored. The fix moved
  `load_dotenv()` before the `ai_engine` import in `app.py` and changed model resolution to
  a lazy read inside `get_ai_recommendations()`.
- **Fallback logic and JSON handling improvements** — Bob reviewed and helped improve the
  `_fallback_recommendations()` function and the defensive `_extract_json()` parser.
- **Regression tests** — Bob helped write and verify `test_model_name.py`, a four-case
  test suite that confirms the correct Gemini model name is sent to the API under all
  relevant conditions (default, env-var override, simulated dotenv, and regression against
  the old default).
